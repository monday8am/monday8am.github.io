6 · The harness
The harness around the machine
pure
step decides
  • Where the tap goes next
  • Told the journal entry, never reads it
  • Rule 3a: whether a write is journalled
impure · one per arming
TapRunner remembers
  • Reads the journal at detect and hands it to step
  • Runs the band rule and the ready gate before the machine
  • Asks the flow at Deciding and feeds Decided back, so no caller ever sees Deciding
  • Journals the write, then spends the token (each app's own policy)
  • On Written: forgets the journal, keeps lastRecord, answers the screen on main
the SDK edge
WristbandTaps touches the chip
  • SDK callbacks become events
  • Enrols blank bands, retries while the tap lives
  • Drops faults the operator never saw
  • Disarms once answered, never after a fault
The order is the point: a write journalled and then torn is finished by the band's next tap. One torn before it was journalled is lost, and the guest's money with it.

8 · Linking the activities
The screen arms; PulseraManager still decides
// onCreate, after its PulseraManager flows = new CashlessFlows(pulseraManager); // arming: the amount is frozen here WristbandModule.taps().arm(     flows.topUp(amount), tapScreen); // the answers, on the main thread new TapScreen() {   onWritten(WristbandData record) {…}   onRefused(TapRefusal refusal) {…} };
Inside topUp, decide is pm.flujoRecargarPulsera(record, amount, resumed): the business logic is untouched.
Where it rubs
  1. Flujos run on the reader thread, inside the 5 s tap budget: nothing can be drawn in decide.
  2. Values are frozen at arming. Only what the operator edits while armed is a function: Ticket's cups.
  3. One CashlessFlows per screen, after its PulseraManager. A writing operation without one fails at arming.
  4. wristbandDataReaded becomes flows.getLastRecord() (50 calls). A resumed top-up replaces it, so CantidadVasos takes onServed.
  5. Java screens get TapScreen callbacks. Logs name the screen by its enclosing class: R8 would need a keep rule.
  6. The reader switches off once the screen is answered, not after a fault. A screen that keeps listening arms again.
